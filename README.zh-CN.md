# Base Path Updater

移动文件夹后，让 Obsidian Bases 中的路径引用自动跟着更新。

例如，你把 `Work/Research` 移到 `Archive/Research`，原来按这个文件夹筛选的 Base 会自动使用新路径，无需逐个打开修改。

[English](README.md)

## 能做什么

- **自动更新路径**：响应文件夹重命名和移动，同时处理其子文件夹、文件的路径引用。
- **支持多个视图**：检查 Base 的全局筛选、各视图筛选和公式。
- **查看历史并撤回**：列出涉及的 Base 文件和路径的前后变化，支持撤回一整次操作。
- **日常使用保持轻量**：不定时扫描，不因普通笔记编辑而运行；只在文件夹路径变化时检查 Base。

## 安装

需要 Obsidian **1.9.0 或更新版本**，并启用内置的 **Bases** 插件。当前版本可以手动安装，尚未列入社区插件目录。

1. 将本项目构建得到的 `dist/base-path-updater` 文件夹复制到仓库的 `.obsidian/plugins/` 中。
2. 确认插件目录里有 `main.js`、`manifest.json` 和 `styles.css`。
3. 重新加载 Obsidian，在「设置 → 第三方插件」中启用 **Base Path Updater**。

如果你下载的是源码，先按[开发文档](docs/IMPLEMENTATION.zh-CN.md#开发与构建)生成安装文件。

## 使用与撤回

启用后，在 Obsidian 中移动或重命名文件夹即可。发生更新或异常时，插件会显示通知。

打开历史记录有三种方式：

- 点击侧边栏的文件夹同步图标，选择「查看更新历史 / 撤回」。
- 在命令面板中搜索 **Base Path Updater**。
- 进入插件设置，点击「查看历史 / 撤回」。

展开记录可以查看每个 Base 中路径从什么改成了什么，点击「撤回 Base 修改」即可恢复。历史会在重启后保留，最多保存最近 **30 次操作**；快照容量约 **5 MiB**，达到容量时会先移除最旧的记录。单次操作过大时，超出容量的文件会被跳过并说明原因。

**撤回只恢复 Base 内容，不会把文件夹移回原处。** 如果希望筛选继续有效，请将文件夹恢复到对应位置。连续操作建议从最新记录开始撤回。文件被手动编辑、被后续操作修改或已删除时，插件会跳过该文件并显示原因，避免覆盖新内容；同一次操作中的其他文件仍可撤回。

## 支持的路径写法

| 写法               | 示例                                     |
| ------------------ | ---------------------------------------- |
| 按文件夹筛选       | `file.inFolder("Work/Research")`         |
| 按完整文件路径筛选 | `file.path == "Work/Research/笔记.md"`   |
| 按路径开头筛选     | `file.path.startsWith("Work/Research/")` |

支持单引号、双引号，以及将路径写在等号左边。匹配区分大小写，只更新原文件夹本身及其下级路径：移动 `Work/Research` 不会修改 `Work/Researcher`。

使用 `startsWith` 筛选文件夹时，建议像示例一样保留末尾的 `/`，避免同时匹配名字相近的文件夹。

## 使用范围

- 仅处理独立的 `.base` 文件，不处理 Markdown 中内嵌的 `base` 代码块。
- 仅响应文件夹的移动和重命名；单独重命名笔记文件不会触发路径更新。
- 支持明确写出的固定路径；拼接路径、变量、正则表达式和其他未列出的写法不会自动改写。YAML 锚点、别名和自定义标签也不会展开修改。
- 不修改视图名称、属性显示名称或普通文字。命中的筛选或公式可能改用 YAML 双引号形式，内容含义保持不变。
- 插件关闭期间的移动不会补处理；在外部文件管理器中操作，也取决于 Obsidian 是否识别为文件夹重命名事件。
- 历史仅存放在当前仓库的插件目录中，不进行网络请求；历史不是完整的仓库备份。
